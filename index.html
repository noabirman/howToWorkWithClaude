01 · Quick start

From install to first task

You need a terminal, a project folder, and a Claude account (Pro, Max, Team, Enterprise, or a Console/API account).

Install

Pick your operating system. The native installer updates itself in the background.

curl -fsSL https://claude.ai/install.sh | bash
PowerShell
irm https://claude.ai/install.ps1 | iex

Tip: install Git for Windows so Claude can use the Bash tool. Otherwise it falls back to PowerShell.

macOS
brew install --cask claude-code
Windows
winget install Anthropic.ClaudeCode

These don't auto-update. Run brew upgrade or winget upgrade yourself.

check it worked
claude --version

Open your project and launch

Claude works inside the folder you start it in. Pick a small practice project first. On first launch it opens your browser so you can log in.

# go to your project
cd path/to/your/project
# start Claude
claude

Give it a first task

Start by asking, not changing. This is the safest way to learn what Claude sees.

explain what this project does and how it is organized
which file would I edit to change the page title?
add a README section that explains how to run this project

Claude will propose edits and ask permission before changing anything. Read each prompt, then approve or decline.

⚡

One-shot mode

Get an answer and exit, perfect for scripts.

claude -p "summarize this repo"
cat error.log | claude -p "explain this"
↩︎

Come back later

Sessions are saved. Continue where you stopped.

claude -c      # latest session here
claude -r      # pick from a list
🆘

Stuck?

Inside Claude, type /help, or run /doctor to diagnose your setup. Press ? on an empty prompt for shortcuts.

02 · Mental model

How an agent actually works

A chatbot answers. An agent acts: it uses tools, looks at the results, and decides what to do next. Understand this loop and every other feature makes sense.

PHASE 1Gather context

Reads files, searches code, runs read-only commands to understand the situation.

PHASE 2Take action

Edits files, runs commands, calls tools. Asks you first when it matters.

PHASE 3Verify results

Runs tests or the build, reads the output, and fixes what broke.

↻ It repeats until done, and you can interrupt any time with Esc.

The tools Claude uses

ToolWhat it doesAsks permission?
ReadReads file contentsNo
Grep / GlobSearch inside files / find files by name patternNo
Edit / WriteChange part of a file / create or overwrite a fileYes
BashRun shell commands (tests, git, installs…). Common read-only ones run freely.Yes
WebFetch / WebSearchRead a URL / search the webYes
AgentSpawns a subagent with its own fresh contextDepends
AskUserQuestionAsks you a multiple-choice questionNo

The context window: Claude's short-term memory

Everything lives in one window: your conversation, files Claude read, command output, your CLAUDE.md, and loaded skills. When it fills up, quality drops and early instructions can get lost. Managing context is the #1 skill.

  • Claude auto-compacts when near the limit: it clears old tool output, then summarizes.
  • /context shows what's filling the space.
  • /clear starts fresh between unrelated tasks. CLAUDE.md still loads.
  • Rules that must survive go in CLAUDE.md, not in chat.
⏪

Checkpoints: Claude snapshots files before editing. Press Esc Esc on an empty prompt or type /rewind to roll back. It only tracks Claude's edits, so keep using git too.

03 · Staying in control

Permission modes

Modes decide what Claude may do without asking. Press Shift+Tab to cycle. The bottom status bar always shows the current mode.

Shift+Tab cycle:Manual→Edit automatically→Plan→Auto→ back
Best for learning

Manual default

Only reads run freely. Claude asks before every edit, command, or network call.

--permission-mode default
Safest for big changes

Plan plan

Claude researches and writes a plan but edits nothing. You approve the plan first. Also: /plan fix the login bug.

--permission-mode plan
Faster

Edit automatically acceptEdits

File edits (and basic file commands like mkdir, mv, cp) inside your project skip the prompt. Other commands still ask.

--permission-mode acceptEdits
Fewer prompts

Auto auto

A separate classifier model reviews actions and blocks risky ones. Reduces prompts but is not a guarantee of safety.

--permission-mode auto
⚠️

Check your starting mode. Recent versions (v2.1.283+) may start new terminal sessions in Auto. Look at the status bar, and if you want Manual, press Shift+Tab or set "defaultMode": "default" in ~/.claude/settings.json.

⛔

Never use --dangerously-skip-permissions (bypass mode) on your real computer. It removes every prompt and is meant only for disposable containers or VMs.

06 · Teach it your project

Memory: CLAUDE.md

Claude starts every session knowing nothing about you. CLAUDE.md is a plain text file it reads at launch. Put there what it can't guess from the code.

CLAUDE.md
# Project: Student Planner

## Commands
- Run app: `npm run dev`
- Test one file: `npm test -- path/to/file`
- Lint before finishing: `npm run lint`

## Style
- Use ES modules (import/export), not require
- Keep functions under 40 lines

## Rules
- Never edit files in /dist
- Ask before adding a new dependency

See @README for the overview.

Create a starter instantly with /init. Edit with /memory. Keep it under ~200 lines; long files get ignored.

WhereApplies to
~/.claude/CLAUDE.mdYou, in every project
./CLAUDE.mdThis project, shared via git
./CLAUDE.local.mdYou only, this project (gitignore it)
subfolder/CLAUDE.mdLoaded when Claude works there
  • Write: commands Claude can't guess, style that differs from defaults, gotchas, repo etiquette.
  • Skip: things obvious from the code, long tutorials, anything that changes weekly.
  • Auto memory: Claude also keeps its own notes in ~/.claude/projects/…/memory/. Toggle with /memory.
💡

CLAUDE.md is advice, not enforcement. For a rule that must never break, use a deny rule or a hook. And never put passwords or keys in it: it's committed to git.

07 · Level up

Extend Claude

Once the basics click, give Claude reusable abilities. Each piece below solves a different problem.

Skills = reusable playbooks

A skill is a folder with a SKILL.md: instructions Claude follows when relevant, or when you type /skill-name. Perfect for “how we do X here”. Old .claude/commands/*.md files still work, but skills are the recommended format.

  • Personal: ~/.claude/skills/<name>/SKILL.md
  • Project: .claude/skills/<name>/SKILL.md
  • List yours with /skills
  • disable-model-invocation: true means only you can trigger it
.claude/skills/fix-issue/SKILL.md
---
name: fix-issue
description: Fix a GitHub issue
disable-model-invocation: true
---
Fix GitHub issue $ARGUMENTS following our standards.
1. Read the issue description
2. Implement the fix
3. Write tests
4. Create a commit

# then run:  /fix-issue 123

Subagents = specialist helpers

A subagent works in its own fresh context window and reports back a summary. Use them so long research doesn't clutter your main conversation.

  • Built in: Explore (fast read-only search), Plan, general-purpose
  • Just ask: “Use subagents to investigate how auth works”
  • Custom ones live in .claude/agents/
.claude/agents/code-reviewer.md
---
name: code-reviewer
description: Reviews code for quality and best practices
tools: Read, Glob, Grep
model: sonnet
---
You are a code reviewer. Analyze the code and give
specific, actionable feedback on quality, security,
and best practices.

Hooks = guaranteed automation

Hooks are shell commands that run automatically at certain moments (before/after a tool, on session start…). Unlike CLAUDE.md, they always run.

  • PreToolUse can block an action (exit code 2)
  • PostToolUse runs after, e.g. auto-format
  • Inspect with /hooks
.claude/settings.json: format after every edit
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
      }]
    }]
  }
}

MCP = plug Claude into other tools

The Model Context Protocol connects Claude to outside services: issue trackers, docs, databases, design tools. Only add servers you trust.

  • Scopes: local (default), project (.mcp.json, shared), user
  • Manage with claude mcp list or /mcp
add a remote server
claude mcp add --transport http notion https://mcp.notion.com/mcp
add a local server (note the --)
claude mcp add --transport stdio airtable \
  --env AIRTABLE_API_KEY=YOUR_KEY \
  -- npx -y airtable-mcp-server

Plugins = installable bundles

A plugin packages skills, subagents, hooks, and MCP servers so you can install them in one step, like an app store for Claude.

  • Browse and install with /plugin
  • Plugin skills are called /plugin-name:skill-name
terminal
claude plugin install code-review@claude-plugins-official
claude --plugin-dir ./my-plugin   # try a local one
08 · Get better results

Prompting that works

Claude is a very capable teammate who knows nothing about your situation. Be specific, give it examples, and give it a way to check its own work.

✕ Vague

fix the login bug
make it better
add tests

✓ Specific + verifiable

Users report login fails after session timeout. Check token refresh in @src/auth/. Write a failing test that reproduces it, then fix it and run the tests.
Add a validateEmail function. user@example.com → true, user@.com → false. Run the tests after.

The golden workflow: Explore → Plan → Code → Commit

Use it for anything bigger than a one-line fix.

1 · Explore

Understand first

Switch to Plan mode (Shift+Tab).

read /src/auth and explain how sessions and login work
2 · Plan

Agree on a plan

Review it. Ctrl+G opens it in your editor.

I want to add Google OAuth. Which files change? Make a plan.
3 · Code

Build and verify

Approve the plan and let it run tests.

implement the plan, write tests, run them, fix failures
4 · Commit

Save your work

Review with /diff first.

commit with a clear message and open a PR

Prompt power-ups

  • Name files with @path instead of describing them.
  • Point to a pattern: “follow how @Button.js is written”.
  • Paste screenshots of UI bugs (Ctrl+V).
  • Pipe logs: cat error.log | claude -p "explain"
  • Ask it to ask you: “Interview me about requirements before coding.”
  • Test-first (TDD): “Write tests, confirm they fail, then implement. Don't change the tests.”

Everyday git help

what files have I changed?
create a branch called feature/dark-mode
show me the last 5 commits
help me resolve these merge conflicts
commit my changes and open a PR

09 · Good habits

Context hygiene & staying safe

Most “Claude got dumb” moments are a full or messy context. Most “Claude broke it” moments are missing safety nets.

🧹

Reset between tasks

/clear when switching topics. Stuck after two failed corrections? /clear and write a better first prompt.

🗜️

Compact with focus

/compact focus on the API changes keeps what matters.

💬

Side questions

/btw what does this flag do? answers without polluting history.

🔍

Delegate research

“Use subagents to investigate X” keeps file dumps out of your main chat.

Common mistakes

  • Kitchen-sink session: unrelated tasks in one chat. → /clear
  • Endless correcting: arguing in circles. → restart with a better prompt
  • Bloated CLAUDE.md: Claude ignores walls of text. → prune it
  • Trusting without checking: → require tests or a build
  • “Investigate everything”: → scope it or use a subagent
  • Approving prompts without reading: → read what it will run

Safety checklist

  • Use git. Commit before big tasks, so any mistake is one command from undone.
  • Start in Manual or Plan mode until you trust what you see.
  • Review diffs with /diff before committing.
  • Protect secrets with deny rules (see below). Never paste real keys into prompts.
  • You are responsible for the code you submit. Understand it, and ask Claude to explain.
  • Follow your course's AI policy on assignments.

settings.json: allow & deny

Rules are Tool(specifier). Deny always wins, in every mode.

~/.claude/settings.json (strict JSON, no comments)
{
  "permissions": {
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run test *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)"
    ]
  }
}

Precedence (high→low): managed → command line → .claude/settings.local.json → .claude/settings.json → ~/.claude/settings.json. Use /config or /status to see what's active.

Models

Switch with /model or Option/Alt+P. Rule of thumb: Sonnet for daily work, Opus for hard problems, Haiku for quick simple tasks.

AliasMeaning
sonnetLatest Sonnet: balanced daily coding
opusLatest Opus: complex reasoning
haikuLatest Haiku: fast and light
fable / bestMost capable, for the hardest long tasks, where available
opusplanOpus while planning, Sonnet while executing
sonnet[1m]1M-token context variant

/effort sets how hard Claude thinks (low → max). More effort means slower and costlier, so raise it only for hard problems.
